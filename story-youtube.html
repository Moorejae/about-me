An automated YouTube channel

Script to upload with no human in the loop, and the Google verification work that made it legitimate to actually publish.

Built forEmmanuel’s channel
RoleDesign, pipeline, verification
VerifiedGoogle sensitive scope, YouTube Manager

The brief

Emmanuel wanted a channel that could keep publishing without him becoming a full-time video editor. The ask was not "generate a video", it was "own the whole loop, reliably, on a schedule".

The pipeline

  1. Script. Topic and angle are chosen against a content plan, then written to a fixed structure so the pacing stays consistent across episodes.
  2. Voice. Narration is generated by TTS Spaces I host myself, not a paid voice API, F5-TTS and Higgs TTS 3, so the voice layer is a component I control rather than a vendor I depend on.
  3. Assemble. Visuals, audio and timing are stitched into a render ready for upload, with the metadata that goes with it.
  4. Publish. The finished video is uploaded through the YouTube Data API, with title, description and visibility set programmatically.

The part that is not glamorous: Google verification

Uploading and managing a channel through the API is not a public scope. The YouTube Manager permission is a sensitive scope, which means an app cannot ship it to real users until Google has reviewed how it is used. Passing that review is a project in itself:

  • A consent screen that tells the truth. The app name, logo, support contact and the exact scopes requested had to match what the app actually does, no "manage your YouTube account" hand-waving.
  • Scope justification. Each sensitive scope needed a specific, concrete explanation of which feature required it and why a narrower scope would not work.
  • A demonstrable flow. Reviewers have to see the actual authorisation and upload path working, not a mock-up.
  • Policy compliance. A published privacy policy, a clear statement of what data is accessed and stored, and behaviour that matches it, because approval is revoked when the app does something different from what it declared.
Why this matters to a hiring managerAnyone can call an API with their own key. Getting an app verified to do it on behalf of other people is an engineering and compliance exercise, and that is the part I actually shipped.

Vertex AI in the loop

Model calls for scripting and metadata run through Google Vertex AI, which keeps the generation inside a Google Cloud project with its own IAM, quotas and audit trail rather than a personal API key. For a client build that is the difference between a demo and something that can be handed over.

What makes it survivable

  • Idempotent publishing. A retry must never create a duplicate upload, so each episode carries an identity the pipeline checks before it acts.
  • Fail visibly. Every stage writes its outcome; a silent stall is worse than a loud failure.
  • Config over code. Schedule, voice and formatting changes are environment changes, not edits to the pipeline.

What Emmanuel said

Emmanuel, channel owner“Victor set up the whole channel so it runs without me. I record nothing, I edit nothing, I just check what went out and plan the next topic. It gave me back my evenings.”
